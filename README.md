# 견적핏 — 로컬 시연 제품

경진대회 주제 **02 업무혁신·생산성 향상**. 제공한 가상 요청서와 회사 조회표를 사용해 견적·발주 조건을 재검증한다. 기존 기획 문서는 설계 시점의 기록이며 현재 구현 범위는 이 문서와 검증 기록을 기준으로 한다.

## 소스 받기

```bash
git clone https://github.com/lee090626/quotefit.git
cd quotefit
```

## 실행

```bash
./실행.command
```

브라우저에서 **http://127.0.0.1:8765**를 연다. 서버 종료는 터미널에서 Control+C. Python 3.10 이상과 PDF 읽기용 `pypdf`가 필요하다. 실행 스크립트는 설치된 Python 환경을 확인한다.

```bash
python3 -m pip install -r requirements.txt
python3 server.py
```

화면과 계산·저장 기능은 외부 계정 없이 동작한다. **AI 판단**에는 설치된 Ollama와 `qwen3:0.6b`가 필요하다. 모델 준비 여부는 ./실행.command --점검으로 확인한다. 다른 컴퓨터의 최초 실행에서는 다음을 실행한다.

```bash
ollama pull qwen3:0.6b
ollama serve
```

Ollama가 이미 실행 중이면 다시 시작하지 않는다. 모델 연결 실패나 허용되지 않은 응답은 명시적으로 **규칙 경로 사용**으로 기록하며 AI 성공으로 표시하지 않는다. 입력·도면·계산 결과는 외부 LLM 서비스로 보내지 않는다.

## 한 번의 시연

1. 영업일 0에서 ‘최초 요청 불러오기’ → ‘검증 시작’.
2. P03 재질 확인값에 `AL6061` 입력 → 다시 검증. 초기 견적 **1,000,000원·5영업일** 저장.
3. ‘발주 변경 불러오기’. 시연 시점이 영업일 4로 진행되고 P01이 10→20개로 바뀐다.
4. ‘검증 시작’. 최신 조건 재조회 후 표준 **1,140,000원·7영업일**, 긴급 소재·외주 **1,200,000원·5영업일**을 비교한다.
5. 5영업일 대안을 내부 승인한다. 7영업일 표준 조건은 고객과 납기 변경에 합의했다는 확인이 있어야 승인할 수 있다.
6. 저장 이력에서 V1/V2와 원문·계산 근거를 다시 보고 JSON을 내려받는다. 외부 발송·구매 발주·재고 예약은 수행하지 않는다.

PDF 입력은 [가상 견적요청 PDF](./output/pdf/견적핏_가상견적요청.pdf)를 사용한다. 텍스트 추출 가능한 PDF만 지원하며 스캔 이미지 OCR·복잡한 형상 해석은 지원하지 않는다. 파일 제한은 화면에서 5MB다.

## 시연을 반복할 때

시계는 같은 저장소 안에서 뒤로 돌리지 않는다. 영업일 7에는 기존 조회 조건이 만료된다. 처음부터 새로 시연하려면 실행 중인 앱 서버를 Control+C로 종료하고 다음을 실행한다.

```bash
./실행.command --새시연
```

`data/demo-날짜-시간.sqlite3`에 새 기록을 저장한다. 이전 저장소는 삭제하지 않는다. 같은 기록을 이어서 사용하려면 해당 파일을 `QUOTE_FIT_DB`로 지정해 실행한다.

## 구현 범위

| 구현 | 제한 |
|---|---|
| 실제 로컬 LLM의 다음 행동 선택, 실패 결과에 따른 재계획 | 경량 모델의 계획을 허용 목록·목표 검사로 제한. 자유로운 공장 운영 판단은 아님 |
| PDF 텍스트 추출·메일/텍스트 입력·누락 재질 확인 | 제공한 가상 P01~P10 표 형식, P01 10→20 변경 요청 전용 |
| 승인 원가·재고·생산 여력 조회, 정수 금액·납기 계산 | 실제 ERP·공급사·공장 일정 미연동, 가상 표 기준 |
| 견적 버전·승인 작업·실행 로그 SQLite 저장과 재조회 | 한 컴퓨터의 로컬 시연용, 여러 담당자의 인증·권한 체계는 범위 밖 |
| 변경·만료·이전 버전 승인 차단, 납기 변경 합의 확인 | 전자계약·실제 수주 확정·외부 전송을 수행하지 않음 |

일반 기업 문서를 자동 이해하는 범용 제품이나 상용 완성품으로 소개하지 않는다. 실제 기업 작업시간 절감·구매 의향·도입 효과는 아직 측정하지 않았다.

## AI·도구 구분과 출처

- **AI:** Ollama의 Qwen3 모델이 구조화된 상황과 허용 행동을 받아 다음 행동을 선택한다. 전체 업무를 독립적으로 분해·계획하지 않으며 단일 허용 행동 단계도 있다. 원문을 임의로 가격 규칙이나 승인 명령으로 실행하지 않는다.
- **계산·검증:** Python 코드가 사양·지원 수량·재고·공정·가격 규칙을 검증한다. 금액은 원가 × 5/4이며 예제 금액은 정확히 나눠진다. 다른 반올림 정책을 만들어내지 않는다.
- **상태:** SQLite에 견적 버전·승인·조회 기준·원문·실행 기록을 남긴다. 모델 출력은 계산·저장 권한을 바꿀 수 없다.
- **모델 이유:** 원본 모델 응답은 기록 안에 보존한다. 한국어 요약이 서버의 검증된 사실로 작성된 경우 그 출처를 별도로 표시한다.
- **입력 자료:** 직접 만든 가상 자료. 실제 기업의 코드·도면·단가·이메일은 포함하지 않는다.
- **라이브러리:** Python 표준 라이브러리, PDF 읽기 `pypdf`, 모델 실행 Ollama. Qwen3 모델의 제공 페이지에는 Apache 2.0 라이선스가 명시돼 있다. [모델 정보](https://ollama.com/library/qwen3:0.6b), [로컬 Chat API](https://docs.ollama.com/api/chat).
- **개발 지원:** Codex로 이 로컬 MVP 코드·가상 입력 PDF·설계 및 검증 문서를 작성했다. 구현 전 기획 자료와 신규 구현 코드를 구분해 제출할 수 있다.

## 확인 방법

```bash
python3 -m unittest -v test_core.py
node --check app.js
```

`test_core.py`는 임시 SQLite 저장소를 사용한다. 최종 실제 AI·HTTP·브라우저 검증 결과는 [최종 검증](./FINAL_VERIFICATION.md)에 정리한다. 규칙 테스트 통과를 실제 모델 호출·기업 사용 효과의 증거로 대체하지 않는다.

## 촬영용 새 저장소와 실행 점검

```bash
./실행.command --점검
./실행.command --새시연
```

점검은 DB를 만들거나 서버를 시작하지 않는다. 8765 포트가 사용 중이면 기존 서버를 확인하고 해당 터미널에서 정상 종료한 뒤 다시 점검한다. 새 시연은 기존 DB를 보존하며 새 data/demo-날짜-시간.sqlite3를 사용한다. Python은 QUOTE_FIT_PYTHON, 활성 가상환경, 설치된 Codex 런타임, 시스템 python3 순서로 선택한다. 다른 컴퓨터에서는 Python 3.10+와 requirements.txt 설치를 준비한다.

회귀 테스트는 실행 스크립트가 표시한 Python으로 `-B -m unittest -v test_core`를 실행한다. 모델 가중치와 Ollama 런타임은 포함하지 않는다. pypdf>=6.0을 유지했으며 의존성을 변경하지 않았다.
